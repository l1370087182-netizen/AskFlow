# 全链路降级策略盘点

> 版本：v0.9（2026-09-07）
> 原则：每个依赖挂掉都有明确的退路，主流程永不整体失败。读路径尽量降级（坏一点点也能用），写路径保守（删数据/发邮件这类不可逆操作，失败就停下来或宁保留）。

---

## 一、检索链路（对话的入口）

| 故障点 | 降级成什么 |
|---|---|
| Milvus 连不上（启动时或检索时） | **纯 BM25 检索**，对话照常（`hybird.py:99,129`） |
| Rerank 服务挂掉 | 不精排，直接用 **RRF 融合分排序**，且这批结果**不做 0.3 相关度阈值过滤**（防止降级期误杀全部结果）（`hybird.py:31,38`） |
| 检索编排（多查询改写）失败或超 5s 预算 | **用原始 query 直接检索**，跳过改写/融合环节（`retrieval_orchestrator.py:4,24`） |
| 检索结果过相关度阈值后为空（知识库真没资料） | **不硬答**：标注「非知识库资料」用模型自身知识简答 + 触发联网补爬异步补库 |
| knowledge 语料查不到但术语表有 | 拼入【术语卡片】块垫底（`chain.py:115`） |
| 术语表也没有 | 模型说明「知识库无资料」，不编造 |

## 二、LLM 调用链路（v0.9 用户自带模型）

| 故障点 | 降级成什么 |
|---|---|
| 用户未配置模型（`build_llm_for_user` → None） | 对话/面试 SSE 发 `no_model` 错误气泡（带「去配置」按钮）；JD 分析/爬取入口 400 引导。**这是唯一「不降级、明确报错」的地方**——核心功能没有 LLM 就没有意义，宁可明确说 |
| 后台 Agent（producer/reviewer/planner/searcher）无模型 | 各自**纯规则模式或跳过该步**，任务不失败 |
| 费曼评分正则解析不出分数 | LLM 兜底提取；LLM 也失败 → **保留正则能拿到的部分**，score 留空（`evaluator.py:122-128`） |
| 面试总评「薄弱点」解析失败 | 同样正则 → LLM 兜底 → 空列表 |

## 三、任务引擎 / 爬虫链路

| 故障点 | 降级成什么 |
|---|---|
| Redis 不可用（分布式锁） | **放行、降级为无锁竞争**，靠数据库 CAS 保证正确性，绝不阻塞任务（`locks.py:39-45`） |
| Redis 不可用（爬取进度查询） | 任务板只剩 **DB 状态视图**，没有实时进度条（`board_controller.py:103`） |
| 单页抓取失败 | 记入失败页，**逐页降级继续**爬后面的，整站不中断（`producer.py:92`） |
| AI 清洗单页失败 | **回退用原始正文**入库（`knowledge_service.py:148`） |
| 联网搜索：未配 `SEARCH_API_KEY` / 无用户模型 / 达并发上限 | **静默跳过补爬**，主回答照常 |
| 向量化失败（Embedding API 挂等） | 知识行置 `status=2` + `vector_error` 落库，**不阻塞其他知识入库**，前端可一键重试 |
| Milvus Lite 被占用 | 混合检索走 BM25 降级；`vectorize.py` 有后端存活检测，避免双开 |

## 四、质量门禁

| 故障点 | 降级成什么 |
|---|---|
| LLM 评分失败（裁判罢工） | **keep + 分数记 NULL（待补审）**，绝不删——删除不可逆，宁混入垃圾不误杀干货 |

## 五、基础设施杂项

| 故障点 | 降级成什么 |
|---|---|
| SMTP 未配置 | 验证码 **print 到后端控制台**（本地开发兜底） |
| 旧会话 JSON 缺字段 / evaluate 的 JSON 列损坏 | 结构兜底补默认值 / 降级为空数组 |

---

## 六、设计口径总结

降级有三档，按「这步失败是否摧毁功能意义」决定：

1. **有等价退路**（最常见）：换一条路走到同一目的地——向量挂了用 BM25、AI 清洗挂了用原文、锁挂了用 CAS
2. **功能悄悄缺席但不伤主流程**：联网补爬、进度条、术语兜底——少了只是体验打折
3. **不降级、明确报错**：只用在「退路等于功能消失」的场景——用户没配模型、密码错误。此时宁可给清晰的引导，也不给假成功

判断原则：**读路径尽量降级，写路径保守**——不可逆操作（删除、发邮件、判废）失败时宁保留、宁停住，绝不悄悄替用户做不可逆的决定。
