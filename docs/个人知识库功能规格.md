## 一、背景与目标

现有知识库为**全局共享语料**（爬虫 + 上传），个人无法添加/修改/隔离。本功能：

1. 用户**添加**自己的知识：① 手工 标题+正文；② 提交 URL 由系统 **shallow 爬整站**（目标页+同域链接，默认 ≤10 页，钳制 1..20）。
2. 爬取后用 **AI 清洗整理**正文再入库（逐页独立降级：失败/垃圾输出→回退原文）；AI 用**该用户已保存的私有模型配置**（`user.llm_*`），未配置→提交爬取时 400 提示去 ⚙️ 配置。
3. 个人知识**参与该用户对话检索**（讲解 build_ask + 费曼选题）；全局知识所有人可检索；个人条目**仅本人**检索/查看。
4. 用户可**编辑/删除**自己条目；**不可越权**（读路 404 隐藏存在、写路 403 明示）。
5. 全局知识（爬虫/旧上传）语义不变；全局视图（列表/分类/统计/检索）不得泄漏个人条目。

## 二、已确认决策

| 项 | 决策 |
|---|---|
| 归属表达 | `knowledge.user_id INT NOT NULL DEFAULT 0`（**0=全局哨兵**，不用 NULL） |
| source_url 唯一约束 | **复合唯一 `(user_id, source_url(700))`**（前缀索引，见 §三.3）；source_url 保持真实值 |
| 手工条目行级键 | 占位 `source_url = manual://{uid}/{secrets.token_hex(8)}`，`source_type="personal"` |
| 爬取任务状态 | **Redis**（状态 JSON + 单用户活跃键）+ 后端进程内**单条常驻后台线程**消费 |
| AI 清洗 | 清洗后入库；单页失败回退原文；手工添加**不**清洗；输入截断 12000 字 |
| 向量化 | 逐页/单条即时 `ingest_row`；pipeline 加进程级写锁 |

## 三、数据模型与迁移

### 3.1 `src/model/KnowledgeModel.py`
```python
user_id: Mapped[int] = mapped_column(Integer, nullable=False, default=0, index=True,
                                     comment="所属用户；0=全局知识")
__table_args__ = (UniqueConstraint("user_id", "source_url", name="uq_knowledge_user_url",
                                   mysql_length={"source_url": 700}),)
```
（替换原单列 `uq_knowledge_source_url`。）

### 3.2 `scripts/init_db.py` 迁移（幂等）
1. `ensure_column(...)->bool`：补 `user_id INT NOT NULL DEFAULT 0`（存量行自动落 0）。
2. `ensure_knowledge_unique(conn)`：查 `information_schema.STATISTICS`，单条 ALTER：`DROP INDEX uq_knowledge_source_url, ADD UNIQUE KEY uq_knowledge_user_url (user_id, source_url(700))`（按存在性裁剪子句）。
   > 坑：varchar(768)×4(utf8mb4)=3072 已顶 InnoDB 索引上限，复合必须用前缀 `source_url(700)`；DAO 层保留全值判重兜底。
3. 仅当第 1 步本次真补了列 → `UPDATE knowledge SET status=0`（Milvus 集合将 drop 重建，回灌需要；绑在补列成功分支，重跑不反复清零）。

### 3.3 为什么不用前缀伪 URL
复合唯一让 `source_url` 保持真实值：详情「原文链接」直接渲染、`get_by_url(url, user_id)` 语义干净、不同用户同 URL 天然共存。

## 五、向量化链路
1. `spliter.py`：`Chunk` 加 `user_id:int`；`split_knowledge` 填 `row.user_id`。
2. `VectorStore.py`：schema 加 `user_id INT64`；**`_ensure_collection` 检测存量集合缺 user_id → drop 重建**（warn：需重跑 /api/embedding/run）；insert 带 user_id；`search(qvec, top_k=5, category=None, uid=0)`：filter `(user_id == 0 or user_id == {uid})`（uid=0 时 `user_id == 0`），与 category `and` 拼接。
3. `pipeline.py`：进程级 `_ingest_lock` 包住「清旧块→写新块」；新增公开 `ingest_row(row)->int`（`_ingest_one`+status 回写，异常置 2 并上抛）；`run(limit)` 不变。
4. `bm25.py`：docs 带 `user_id`；缓存更名 `bm25_cache_v2.pkl`；`search(..., uid=0)`：`d["user_id"] not in (0, uid)` 置 -1（同 category 写法）。
5. `retriever.py`/`hybird.py`：`search` 透传 `uid`（chunk_key/RRF/rerank 零改动）。
6. `chain.py`：`build_ask(message, history, top_k=5, uid=0)`。
7. `chat_controller.py`：`_chat_ask` build_ask 传 uid；`_chat_teach` 选题 `retriever.search(topic, top_k=5, uid=uid)`。
8. `retrieval_controller.py`：加 `Depends(get_current_user)`，`search(..., uid=user.id)`（防调试口泄漏）。
9. `card_controller.overview`：全局计数加 `user_id==0`；返回体加 `my_knowledge: count(user_id==uid, status=1)`。

**防泄漏清单**：GET /、/categories、/{id}、overview、retrieval 调试、BM25、Milvus filter —— 逐条过滤。

## 六、AI 清洗
- `generation/prompts.py` 增 `CLEAN_SYSTEM_PROMPT`：只留主题正文、删导航/菜单/页脚/广告噪音；**不总结/不压缩/不添加原文没有的内容**；保留代码与示例；直接输出正文无客套。
- `generation/llm.py` 抽公共 `build_llm_for_user(db, uid)->ChatLLM|None`（未配置返回 None）；chat_controller 改 `build_llm_for_user(db,uid) or ChatLLM()`（对话保留服务端兜底）；爬取链路对 None 直接失败。
- user 消息=标题+正文（截断 12000 字，尾附「（以下为截断内容）」），`temperature=0.2` 非流式；输出空/<100字/拒答→回退原文，`pages[].cleaned=false`。

## 七、后台爬取任务（`src/service/knowledge_service.py` + `src/spider/shallow_crawler.py` 新建）

### ShallowCrawler（BFS，只抓不存）
`iter_pages(seed_url)` 产出 `{url, ok, title?, content?, links?, error?}`；复用 `crawl_one(url, delay=1)`（middleware 含 3 次重试+退避+UA 轮换）；扩链过滤：同 netloc + http(s) + 剔除二进制后缀 + 未见过 + 未达 max_pages；seed 失败→单条 ok=False 后终止。

### 任务状态（Redis）
- `kb:crawl:task:{task_id}`（TTL 7 天，`task_id=secrets.token_urlsafe(12)`）：`{task_id,uid,url,category,max_pages,status:pending|running|done|partial|failed,done_pages,failed_pages,skipped_pages,current_url,pages:[{url,ok,cleaned,knowledge_id,error}],error,heartbeat,created_at,finished_at}`；每页整体覆写。
- 单用户单活跃：`kb:crawl:active:{uid}`→task_id（TTL 30 分钟，终态删）；已有活跃→409 带回 task_id。
- 多进程保险：线程每轮 `SET kb:crawl:worker {实例} NX EX 30` 抢锁、每页续期。
- 悬挂判定：heartbeat 超 10 分钟→对外呈现 failed。

### 执行流 `_run_task`
独立 `SessionLocal()`；llm=None→failed「未配置大模型」；逐页：抓取失败→failed_pages++；`is_valid_article` 不过→skipped++；AI 清洗→`upsert(user_id=uid, source_type="personal")`→`ingest_row`；总 try/except 置 failed；**必释放 active 键与 worker 锁**。

### SSRF 防护（提交端点）
scheme 限 http/https；`socket.getaddrinfo + ipaddress` 拒绝内网/环回/链路本地地址。

### 启动
`main.py create_app()` 幂等拉起后台消费线程（模块级标记，daemon=True；勿用 uvicorn --reload）。

## 八、接口（`konwledge_controller.py`；`/my*` 声明在 `/{knowledge_id}` 之前）

| 方法 | 路径 | 说明 |

| 现有 GET `/{id}` | 不存在 404；`user_id not in (0,uid)` 404；全局或本人 200 | |
| 现有 GET `/categories` | 默认全局；可选 `scope: global\|mine` | |
| 现有 POST `/`、`/upload` | 不变=全局（user_id=0） | |

## 十一、验收（端到端）
1. 迁移：SHOW INDEX 确认换索引；日志见集合重建；回灌后 overview 全局数与迁移前一致。
2. 注册 A/B；A 手工添加含暗号「穿透哨兵 PENX-ALPHA」→ status=1。
3. 越权矩阵：B 对该条 GET /{id}→404、PUT/DELETE→403；B 的 /my、全局 /、/categories 均无此条。
4. A 清空 /api/user/llm → POST /my/crawl → 400 含 ⚙️ 提示。
5. A 配置后爬真实 URL（max_pages=3）→ 202 → 逐页进度至 done；DB 行 `user_id=A, source_type=personal, status=1` 且正文无导航噪音；连提两次→第二次 409。
6. 检索隔离：A 问暗号→meta.sources 命中个人条目；B 同问不命中。费曼选题个人主题非空。
7. 编辑换新暗号→status 0→1→命中新、旧消失；删除→vectors_removed>0→不再命中；再跑 /api/embedding/run→total=0（无孤儿）。
8. 全局回归：存量对两人均可见；各页无回归。
